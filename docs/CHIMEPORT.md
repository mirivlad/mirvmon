# MirvMon → ChimePort (дополнительный транспорт)

Интеграция использует существующую очередь `notification_outbox`. Она **не заменяет Telegram или SMTP**: на каждое событие (проблема, восстановление, тест, события сайтов и служб) создаётся отдельное задание ChimePort со своей дедупликацией, состоянием и повторными попытками.

## Подготовка ChimePort

Создайте в ChimePort отдельный источник `mirvmon` под нужной учётной записью и токен с правом публикации только в следующие каналы:

- `monitor/hosts` — недоступность серверов, восстановление, метрики и наблюдения.
- `monitor/services` — остановки и восстановление сервисов.
- `monitor/websites` — проверки сайтов.
- `monitor/system` — тестовые уведомления и связность MirvMon.

Не используйте токен Home Assistant или административную сессию. В примере ниже домен `notify.example.org` зарезервирован, а значение `cp_t_EXAMPLE_NOT_A_REAL_TOKEN` **вымышленное**.

## Настройка MirvMon / Portainer

Сначала обновите MirvMon до версии, содержащей миграцию `033_chimeport_notifications.sql` и новый транспорт; миграции выполняются штатным механизмом приложения. Старый образ не умеет обрабатывать ChimePort-задания очереди.

В переменных окружения стека:

```dotenv
CHIMEPORT_ENABLED=1
CHIMEPORT_BASE_URL=https://notify.example.org
CHIMEPORT_TOKEN_FILE=/app/var/chimeport-source-token
```

Адрес замените на собственный HTTPS-адрес. **Реальное значение токена нельзя помещать в Compose, .env, репозиторий или логи.**

Токен хранится в отдельном файле на постоянном Docker volume `app_data`. В контейнере он должен быть доступен процессу MirvMon (UID 10001), с правами `0600`. Создайте этот файл на машине администратора и перенесите защищённым способом в volume, затем удалите временную копию. Не включайте токен в архивы, доступные посторонним. Можно использовать Docker secret, назначив соответствующий путь `CHIMEPORT_TOKEN_FILE`.

По умолчанию `CHIMEPORT_ENABLED=0`, поэтому переход на новую версию сам по себе не включает интеграцию. Отключение ChimePort не влияет на Telegram/SMTP.

## Доставка

- MirvMon сохраняет прежние условия тревог, cooldown, подавление сообщений на обслуживании и дедупликацию. ChimePort получает события из **готовой очереди**; новый опрос не означает новую публикацию.
- Канал ChimePort выбирается по типу события; критические аварии — `urgent`, предупреждения — `high`, восстановление — `normal`.
- Заголовок `Idempotency-Key: mirvmon-outbox-<id>` постоянен для всех повторов одной доставки.
- HTTP `201` и идемпотентный `200` считаются успехом. Ошибка `429` повторяется не раньше времени `Retry-After` (с ограничением до часа), другие ошибки идут в штатные повторные попытки очереди.
- Ошибки ChimePort не заставляют повторно отправлять Telegram: задания изолированы.
- Отправка использует только HTTPS, проверяет сертификат и не следует перенаправлениям с токеном.

## Проверка

1. Убедитесь, что MirvMon и ChimePort healthy; Telegram и SMTP должны работать как раньше.
2. Отправьте тестовое сообщение через стандартную проверку уведомлений MirvMon; при включённом ChimePort появится третье задание в очереди.
3. В веб-интерфейсе проверьте фильтр **ChimePort** и статус `sent`. Проверьте соответствующий канал в ChimePort и Android.
4. Дождитесь реального перехода UP→DOWN и DOWN→UP. Не выключайте реальные сервисы только ради теста.
5. При недоступности ChimePort сообщения остаются в очереди и повторяются; Telegram продолжает приходить.

## Секреты

Никогда не добавляйте настоящий URL частной установки, source token, внутренние адреса или дампы БД в Git. Все значения в этом руководстве — демонстрационные.
