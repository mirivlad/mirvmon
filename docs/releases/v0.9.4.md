# MirvMon v0.9.4

## Что исправлено

- **Потеря Интернета у самого MirvMon больше не превращается в ложные offline/online события отдельных серверов.** Новое server-offline решение теперь разрешено только когда независимый connectivity probe имеет свежий подтверждённый статус `online`.
- Удалена эвристика «массовой потери агентов». Количество одновременно недоступных агентов больше не используется как признак наличия или отсутствия Интернета у центрального MirvMon.
- Состояния connectivity `offline` и `unknown` считаются недостоверным окном наблюдения: в этот период новые offline transitions серверов не создаются, а централизованные сетевые проверки сайтов приостанавливаются.
- После восстановления Интернета каждому агенту по-прежнему даётся его обычный `offline_timeout_seconds` на повторный контакт. Если агент успел вернуться, никакого ложного offline/recovery события для него не возникает.
- После перехода connectivity `offline -> online` MirvMon ставит в штатный notification outbox **одно системное сообщение** с временем начала outage, временем восстановления и общей продолжительностью. Telegram и SMTP используют существующие глобальные настройки и retry-механику.
- Добавлены регрессионные тесты на сценарий, когда во время outage MirvMon успел протухнуть только один агент, на системный outbox и на fail-closed поведение при неизвестном connectivity state.

## Совместимость

Схема БД и agent protocol в v0.9.4 не меняются. Новых Compose services и обязательных переменных окружения нет. Обновление агентов не требуется.

## Обновление

Используйте `ghcr.io/mirivlad/mirvmon:0.9.4`. Достаточно обычного re-pull/redeploy image; отдельной миграции нет.
