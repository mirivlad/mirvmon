# MirvMon v0.6.5

Security and authorization release.

- `user` is now a read-only monitoring role.
- `operator` is available again for bounded operational actions: server maintenance, thresholds/services, alert resolution and agent configuration.
- Only `admin` can create/edit/delete servers or groups, issue installers, rotate credentials, request agent updates, change website definitions, users/system settings or use Backup & Restore.
- Existing database schema already supports `operator`; no migration is required. Existing `user` accounts become read-only and can be promoted by an administrator when operational access is required.
- Production image examples now point at `ghcr.io/mirivlad/mirvmon:0.6.5`, with CI coverage preventing stale pinned release examples.

For Docker/Portainer use `ghcr.io/mirivlad/mirvmon:0.6.5` and perform the normal re-pull/redeploy.
