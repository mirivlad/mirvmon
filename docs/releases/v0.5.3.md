# MirvMon v0.5.3

## Массовое обновление агентов

- На странице серверов для администратора появилось действие **«Обновить все устаревшие»**.
- Перед запуском MirvMon показывает количество подходящих агентов и целевую версию.
- Массовое действие использует тот же проверенный механизм, что и одиночное обновление: для каждого подходящего сервера создаётся обычная индивидуальная update command.
- Уже обновляющиеся, актуальные и требующие ручного обновления агенты безопасно пропускаются.
- После запуска показывается итог: сколько обновлений запланировано, сколько уже выполняется и сколько агентов нельзя обновить автоматически.
- Прогресс отдельных серверов продолжает обновляться существующим polling-механизмом; отдельные rollout campaigns или fleet worker не добавлялись.

## Техническое обслуживание

- Modern native-agent toolchain обновлён до Go 1.26.6.
- Legacy Windows build намеренно остаётся на Go 1.20.14 для Windows 7/8/8.1 и Server 2008 R2/2012/2012 R2.
- Обновлены PHPUnit и PHPStan.
- Публикация GitHub Release теперь выполняется автоматически после успешного tag-driven release pipeline.

## Обновление

- Для Docker/Portainer используйте `ghcr.io/mirivlad/mirvmon:0.5.3` и выполните обычный re-pull/redeploy stack.
- Изменений схемы БД в этом релизе нет.
- Agent protocol не изменён; уже установленные `self_update_v1` агенты можно обновить новой массовой кнопкой после обновления MirvMon.
- Старые агенты без `self_update_v1`, как и раньше, требуют одно ручное обновление актуальным установщиком.
