# MirvMon v0.5.0

## Мониторинг сайтов

- Добавлен централизованный мониторинг сайтов без отдельного Compose-сервиса и
  без изменения протокола native agent.
- Сайт может иметь несколько HTTP(S) endpoints с expected status ranges,
  text assertions, redirect policy, deadline, TTFB/total thresholds, headers
  и explicit auth configuration.
- Проверки TLS отслеживают hostname, issuer и срок действия сертификата;
  проверка домена использует RDAP с ограниченным WHOIS fallback.
- В state read model и TimescaleDB history сохраняются безопасные результаты
  HTTP, TLS и domain checks. Ответы, auth и credentials не сохраняются.

## Инциденты и интерфейс

- Website incidents используют существующие maintenance и notification outbox:
  maintenance подавляет delivery, но не скрывает событие.
- Dashboard, группы и incidents показывают сайты отдельно от серверов, не
  смешивая source identity и status filters.
- Добавлены список сайтов, управление endpoints, detail tabs для overview,
  metrics, events и settings, а также API endpoint метрик сайта.

## Операционная модель

- `website-check-worker` запускается внутри `app`, отмечает heartbeat и
  использует leased queue; network work выполняется вне долгих DB-транзакций.
- Новый параметр `WEBSITE_CHECK_LOOP_INTERVAL` задаёт интервал worker loop;
  значение по умолчанию — 15 секунд.
- Для оценки dashboard read model при 50 и 1000 сайтах добавлен
  `bin/benchmark-websites`.

## Обновление

- Запускайте обычное обновление Compose stack с image tag `0.5.0`; Docker
  entrypoint выполняет `bin/migrate` под advisory lock. Не редактируйте и не
  применяйте вручную прежние migrations.
- Production Compose по-прежнему состоит ровно из `app` и `db`; для
  мониторинга сайтов дополнительный входящий порт или service не нужен.
