# MirvMon v0.9.10 — ChimePort settings in the web UI

## New admin interface

In **Settings → Notifications**, the dedicated ChimePort card allows administrators to enable/disable notifications, enter a server HTTPS address, configure a channel slug (e.g. `servers`), enter or replace the masked source token, and queue a ChimePort-only test message.

The source token is encrypted at rest in PostgreSQL using the same existing MirvMon SecretCipher and APP_KEY as the SMTP and Telegram secrets. It is never returned to the browser.

## Safe upgrade and compatibility

- New database migration `034_chimeport_web_settings.sql` adds optional settings columns.
- Previously installed v0.9.9 instances keep using the existing Docker environment settings until the administrator first saves the new form.
- At first save, the existing token file is automatically imported and encrypted into PostgreSQL. The user does not have to reenter it.
- Subsequently, web settings take precedence over Docker settings, including an explicit off switch.
- SMTP and Telegram remain independent and unchanged; their settings are not overwritten by the ChimePort form.
- Notification queue deduplication, retries and event handling are unchanged. Agent protocol stays compatible.

## Deploy

After CI publishes `ghcr.io/mirivlad/mirvmon:0.9.10`, back up PostgreSQL and re-pull/redeploy MirvMon in Portainer with app_data and db_data preserved. Confirm /readyz, test the ChimePort-only action, and verify existing Telegram notifications.

The old token file may be retained until the web migration has been verified.
