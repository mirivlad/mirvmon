# MirvMon v0.9.3

## Что изменилось

- **Отчёт надёжности сайтов теперь учитывает distributed quorum.** Для каждой центральной автоматической проверки основного endpoint MirvMon берёт свежие результаты выбранных remote agents и применяет тот же failure quorum, который используется live incident pipeline. Missing/stale remote data не считается отказом.
- Assertions остаются централизованными: availability считается успешной только когда quorum transport доступен и Central MirvMon подтвердил assertions.
- В отчёте распределённые сайты явно помечаются количеством точек и quorum.
- На вкладке **События** в деталях сайта добавлена компактная **история точек проверки** за последние 7 дней: переходы доступно/недоступно и последнее состояние каждой Central/agent точки.
- Endpoint с auth, custom headers или `allow_self_signed` по-прежнему не отправляется агентам. Для такого endpoint effective quorum автоматически становится `1`, поэтому отсутствие remote results не может скрыть центральный outage.
- README, ROADMAP, technical specification и документация reliability/distributed probes синхронизированы с фактической семантикой ветки 0.9.

## Совместимость

Agent protocol и схема БД в v0.9.3 не меняются. Новых Compose services и обязательных переменных окружения нет. Существующие агенты с capability `website_probe_v1` продолжают работать без обновления протокола.

## Обновление

Используйте `ghcr.io/mirivlad/mirvmon:0.9.3`. Обычного обновления image достаточно; отдельной миграции для v0.9.3 нет.
