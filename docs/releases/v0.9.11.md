# MirvMon v0.9.11 — Unified notifications settings

## Interface

The **Settings → Notifications** page now has a single, responsive configuration form containing three first-class delivery methods: Email (SMTP), Telegram Bot, and ChimePort.

- The separate ChimePort footer form and its unnecessary description have been removed.
- Global severity levels and notification cooldown appear *below all delivery methods*.
- One **Save settings** button saves changes for all methods in one PostgreSQL transaction; validation failures roll back the entire form.
- Three distinct **Test Email**, **Test Telegram**, and **Test ChimePort** actions save and test only the selected destination, without sending duplicate test notifications via other methods.
- One **Open notification queue** link presents all deliveries and filters.
- Existing secret fields remain masked, with blank fields preserving encrypted credentials. SMTP, Telegram and ChimePort tokens are handled independently.

## Compatibility

No database migration, agent protocol change or new service is required. Legacy POST endpoints continue to work for older forms, but the current UI uses unified save and per-transport test endpoints. Existing SMTP, Telegram and ChimePort settings persist unchanged when upgrading.

## Deployment

Pull/redeploy `ghcr.io/mirivlad/mirvmon:0.9.11` through Portainer while keeping the existing PostgreSQL and application volumes. Check the notifications settings page and independent tests. Telegram remains enabled.
