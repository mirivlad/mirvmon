# MirvMon v0.9.0

## Что изменилось

- Добавлены распределённые HTTP(S)-проверки сайтов через уже установленные MirvMon agents. На сервере агент можно разрешить как probe point, а у сайта выбрать Central MirvMon и нужные удалённые точки.
- Для сайта настраивается failure quorum: transport failure становится агрегированной неудачей только когда недоступность одновременно видит заданное число выбранных точек. После этого сохраняется прежняя защита от дребезга — 3 failure для открытия incident и 2 success для recovery.
- Агент получает `probe_jobs` через обычный outbound `GET /api/v1/agent/config`, не открывает входящий порт и возвращает `probe_results` через обычный metrics envelope и durable delivery queue.
- Remote observations хранятся отдельно в TimescaleDB, поэтому существующие графики, continuous aggregates и reliability сохраняют прежнюю central-only статистическую семантику.
- На странице сайта показываются последние transport-результаты по выбранным точкам. Старые queued probe results сохраняются в истории, но не могут откатить текущее incident state назад во времени.
- Добавлена capability `website_probe_v1`. Сервер не отправляет новые поля remote config старым агентам с strict decoder, поэтому обновление сервера обратно совместимо.

## Семантика удалённых проверок

Remote probe проверяет только transport/HTTP reachability. Auth secrets, custom headers и разрешение self-signed TLS агентам не передаются; content/status assertions, TLS expiry и domain expiry остаются central-only. Central MirvMon всегда участвует в проверке сайта.

## Обновление

Используйте `ghcr.io/mirivlad/mirvmon:0.9.0`. Перед обновлением сделайте резервную копию БД. Миграция 031 применяется автоматически и создаёт назначения probe points и отдельный `website_probe_samples` hypertable. Новых Compose services и обязательных переменных окружения нет.

Сначала можно обновить только MirvMon server: старые агенты продолжат работать с прежним remote config. Чтобы использовать конкретный сервер как распределённую точку, обновите его agent до v0.9.0 (в том числе через существующий self-update), дождитесь capability `website_probe_v1`, затем включите его как точку проверок и назначьте сайту.
