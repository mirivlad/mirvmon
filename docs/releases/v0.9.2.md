# MirvMon v0.9.2

## Что изменилось

- **Central MirvMon теперь всегда участвует в проверке сайта.** В форме распределённых проверок больше нет отдельного выбора центральной точки: администратор выбирает только дополнительные агентские probe points.
- Добавлена миграция `032_central_website_probe_invariant.sql`: существующие сайты с отключённой центральной точкой автоматически переводятся в `central_probe_enabled = TRUE`, а схема БД больше не допускает обратное состояние.
- Семантика распределённых проверок зафиксирована окончательно: агенты выполняют только transport HTTP(S)-проверку. TLS expiry, срок регистрации домена, content/status assertions и performance assertions остаются централизованными функциями MirvMon.
- Убрано служебное пояснение про «первую версию» remote probes из пользовательской формы.
- Карточка **«Всего серверов»** на главном обзоре теперь кликабельна и снимает статусный фильтр, возвращая полный список серверов.
- В отчёте надёжности **доступность сайтов показывается сразу по имеющимся автоматическим проверкам**. Если полнота выбранного периода ниже 95%, результат помечается как **«Неполный период»**, но само значение availability больше не скрывается. Для серверов прежний строгий критерий полноты сохранён.
- Для всех локальных CSS/JS assets добавлен cache-busting по `APP_VERSION`. После обновления MirvMon браузер получает актуальные стили и скрипты без ручного `Ctrl+R`.

## Совместимость

Agent protocol в v0.9.2 не менялся. Remote agents по-прежнему используют capability `website_probe_v1` и передают только transport HTTP(S) observations.

Версия содержит одну миграцию БД. Она автоматически исправляет старые сайты с отключённым Central MirvMon и закрепляет Central как обязательную точку проверки.

## Обновление

Используйте `ghcr.io/mirivlad/mirvmon:0.9.2`. Новых Compose services и обязательных переменных окружения нет; миграция применяется штатным механизмом MirvMon при запуске.
